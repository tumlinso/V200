# B04 — Resident capacity exceeding a single V100

**State:** NOT_RUN. **Owner:** V200-07. **When:** after first real application.

**Code readiness:** Fixture implemented by V200-03/05/07.

## Admission and ceilings

2 exact physical UUIDs, 300 seconds child wall cap, 14336 MiB application allocation cap per GPU, at most 4 CPU threads. Build first. The actual fixture must check headroom and enforce its allocation cap; context overhead is additional and reported. No test window is granted by this document.

## Prerequisites

- Accepted B03
- Both owners have explicit live-free headroom
- Chosen live payload exceeds either constituent capacity; around 24 GiB is a suggested fixture, not an assumption

## Work inside one bounded invocation

1. Check budget including application workspace and reserves
2. Exercise one logical spanning allocation and the selected consumer resident fixture
3. Record physical owner backing and live residency; prohibit silent CPU/managed offload
4. Check results and limited free/reallocation lifecycle
5. Stop without shrinking the proof when headroom is insufficient

## Acceptance

- Actual live resident payload exceeds each single-GPU available capacity
- Correct output and accounting
- No generic 32 GB-free claim

## Stop/defer conditions

- Insufficient headroom => BLOCKED
- Hidden oversubscription/offload
- Any correctness or lifetime failure
