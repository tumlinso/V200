# B01 — Small pair VMM and completion qualification

**State:** NOT_RUN. **Owner:** V200-06. **When:** early foundation.

**Code readiness:** Included example; CUDA compilation and execution pending.

## Admission and ceilings

2 exact physical UUIDs, 90 seconds child wall cap, 512 MiB application allocation cap per GPU, at most 4 CPU threads. Build first. The actual fixture must check headroom and enforce its allocation cap; context overhead is additional and reported. No test window is granted by this document.

## Prerequisites

- Pinned CUDA12.x and actual UUID pair
- CPU example checks and CUDA probe build
- Read-only topology proves selected UUID pair has intended direct NVLink connectivity

## Work inside one bounded invocation

1. Validate controller receipt and visible UUIDs before GPU work
2. Query sm_70, VMM and bidirectional peer capability
3. Create two small owner allocations in one canonical VA, explicit permissions
4. Write disjoint explicit-index ranges; join via cross-device events
5. Read and verify whole range from both GPUs, then release only owned resources

## Acceptance

- Both SM verification paths correct
- Actual rounded bytes and UUIDs recorded
- No claim of app transparency or physical NVLink saturation

## Stop/defer conditions

- Unsupported VMM/peer access
- Wrong pair
- Any mismatch, timeout or uncertain cleanup
