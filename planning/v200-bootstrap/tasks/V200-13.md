# V200-13 — Package a reversible deployment and diagnostic surface

## Durable outcome

Deliver an opt-in application-scoped deployment with accurate identity, compatibility and rollback information.

**Prerequisites:** V200-11, V200-12

## Starting strategy, not a mandatory recipe

Package launcher/facade, versioned profiles and source/binary provenance. Keep native CUDA untouched outside the launch scope. Diagnostics show logical-to-physical mapping and failures. Provide installation/uninstallation steps that do not modify system driver state. Never claim system-wide PCI/NVML device unification unless separately authorized and implemented.

The implementing root may choose another internal tactic using actual code and measured evidence. Local inspect/build/test/review steps stay inside this outcome. Materialize new tasks only for a real ownership, interface, risk or dependency boundary. Do not turn every alternative into a blocking branch.

## Acceptance

- Deployment is reproducible for the accepted profile and removable without altering unrelated GPU software.
- Unsupported APIs, actual transparency tier, capacity reserve and measured performance are plainly documented.
- No hidden watcher/model service/GPU resident daemon is installed.
